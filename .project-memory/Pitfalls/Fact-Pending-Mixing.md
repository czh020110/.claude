# 事实记忆与待定方案混写

## 经验

把用户提出、讨论中或尚未实施的方案/设计决策直接写入项目事实记忆，是可能重复出现的流程性问题，会让后续 agent 将候选内容误认为当前已经生效的项目状态。

## 识别信号

- 内容来自提议、讨论、候选方案或修改要求，而代码、配置和验证结果尚未体现。
- 内容使用“计划”“建议”“待确认”“之后修改”等未来时态，却被放入事实主题。
- 记忆正文找不到对应的实施证据或当前可复现状态。

## 规避方式

- 首次讨论时立即登记到 `TODO/Pending.md`，明确背景、待确认决策、完成条件和关联范围。
- 只有实现完成并通过验证后，才移除 Pending 条目并把最终状态写入对应事实主题。
- 方案被否决或取消时只移除 Pending，不向事实记忆写入候选内容。
