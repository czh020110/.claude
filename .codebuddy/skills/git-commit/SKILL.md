# CodeBuddy 项目级入口

用户明确要求提交时：

1. 先检查 `git status --short`、工作区 diff 和 staged diff。
2. 按修改目的分组，检查密钥、账号、私有路径和临时文件。
3. 运行与本轮变更匹配的验证；不能验证时如实说明。
4. 使用项目约定的 commit 类型和详细说明创建提交；不得添加 AI 署名。
5. 提交完成后确认未忽略工作区干净。

遇到需要用户决定是否提交的本地私有文件时，使用 CodeBuddy 原生用户交互，不要擅自删除或加入提交。提交说明必须覆盖目标、前后状态、关键改动、验证结果和后续事项。
